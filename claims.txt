ASSEMBLER  (asm.c)

Two-pass assembly using a single do_pass() routine called twice:

        Pass 1  (do_pass(src, 1)) - label scan
          - Scans every source line
          - Records each label in the label table at its current PC value
          - Handles SET: assigns a constant value to the label on that line
          - Advances PC for every word-emitting instruction
          - Does NOT emit code; does NOT error on undefined labels
            (forward references are resolved in pass 2)
          - Reports: duplicate labels, invalid label names, unknown
            mnemonics, missing operands, extra operands

        Pass 2  (do_pass(src, 2)) - code generation
          - Resolves all operands; undefined labels are a hard error
          - Encodes each instruction into a 32-bit word stored in obj_code[]

All 19 SIMPLEX instructions correctly encoded
        Instruction word layout:
          bits  7..0  = opcode  (8-bit unsigned)
          bits 31..8  = operand (24-bit signed two's complement)

PC-relative branch offsets:  offset = target_address - (PC + 1)
        because the spec states PC is incremented BEFORE the instruction acts

Pseudo-instruction  data  - emits a raw 32-bit word into object code
Pseudo-instruction  SET   - assigns a constant to a label at assembly
        time; emits no code word

Forward label references resolved correctly in pass 2

Error detection and reporting (written to stderr and .log file):
        - Unknown mnemonic
        - Duplicate label definition
        - Invalid label name  (e.g. starting with a digit: "0def:")
        - Missing operand for instructions that require one
        - Unexpected operand for instructions that take none
        - Extra text after the operand (before any comment)
        - Undefined label reference (pass 2)
        - Invalid operand (neither a valid number nor a valid label name,
          e.g. "08ge")

Warning for labels that are defined but never referenced

Three output files generated (same base name as the source):
        .o   -- binary object file (consecutive little-endian 32-bit words)
        .lst -- listing file (address + hex word + mnemonic + operand)
        .log -- all errors and warnings

Listing file features:
        - Each instruction line: XXXXXXXX YYYYYYYY  mnemonic [operand]
        - Label lines:           XXXXXXXX label:
        - Symbolic operand display (label names shown where possible)
        - Unused-label warnings at the bottom of the listing

Numeric operand formats: decimal, 0x hexadecimal, 0 octal (via strtol)
Case-insensitive mnemonic matching
Portable C11 -- no platform-specific extensions used

EMULATOR  (emu.c)

All 19 SIMPLEX instructions correctly executed
Four CPU registers: A (accumulator), B (second register), PC, SP
32-bit signed integer arithmetic throughout
PC-relative branch evaluation
        (PC is incremented before the branch offset is applied, per spec)
